5.3 Release 1 Increments

Release 1 contains every SHALL requirement of the SRS. To make it buildable and demonstrable by a small team, it is delivered in four increments (fixed by D-32; build slices are planned inside them and do not reorder them). Each increment ends with a demonstration on sample data; later increments build on earlier ones, as {{fig:increments}} shows.

5.4 Indicative Roadmap

The roadmap below is indicative. It assumes work starts on 2 November 2026, two-week sprints, and one developer with AI assistance (PA-01, PA-02). Dates will move with actual progress; the order of increments will not.

5.5 Definition of Done for Release 1

Release 1 is done when all of the following hold. They extend the acceptance approach of SRS Section 8.3.

  1. Every user story of Section 6 marked R1 meets its acceptance criteria in the test environment.
  2. Every business rule BR-01 to {{br-authority}} has an automated test that proves the forbidden case is refused ({{nfr-rulestests}}).
  3. The demonstration scenario of Section 7 runs end to end on seed data with stub adapters.
  4. The interface works in Bahasa Melayu and English and passes an automated WCAG 2.1 AA check on the main participant screens.
  5. The SDD describes the system as built.

5.6 Out of Scope for This Product Version

  • Delivering learning content, live classes or proctoring (UCreds and other tools).
  • Taking academic decisions automatically; MCMS proposes, checks and records, people decide.
  • Native mobile applications; the web interface is responsive instead.
  • Partner-delivered micro-credentials of other institutions as offerings in MCMS.
  • Refund processing and financial accounting.
