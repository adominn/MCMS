2. System Architecture & Technical Infrastructure

2.1 Platform Overview & Technology Stack

UCreds is deployed as a dual-tier web architecture hosted on UTeM's institutional enterprise server infrastructure. The platform pairs a customized learning management engine with an integrated content management knowledge base to deliver both pedagogical content and administrative student guidance.

2.2 Identity Federation and Single Sign-On (SSO)

Authentication on UCreds is bifurcated to accommodate both internal university stakeholders and external lifelong learners:

  • Institutional Users (Staff & Students): Authenticate via the OpenID Connect (OIDC) protocol through Microsoft Entra ID (formerly Azure Active Directory) at endpoint /auth/oidc/. Upon successful federated authentication, accounts are automatically provisioned with university role mappings and linked to UTeM email domains.
  • Lifelong / Industry Learners: Authenticate via Google OAuth2 federation (/auth/oauth2/) or standard internal Moodle credentials (/login/index.php), allowing public candidates to register and purchase modular courses without requiring university matriculation.

2.3 Data Flow & Catalog Retrieval Model

Unlike standard Moodle installations where courses are viewed strictly through a static category hierarchy (/course/index.php), UCreds decouples the public exploration layer from the underlying LMS course structure. When a prospective learner visits https://ucreds.utem.edu.my/catalog/, the client executes an asynchronous POST request to action.php.

2.4 Security Perimeter & Network Isolation

The UCreds platform is guarded by an institutional Web Application Firewall (WAF). During the initial phases of this audit, standard headless automation tools (such as unmodified Puppeteer or Playwright instances) were intercepted with HTTP 500 error responses bearing signature Attack ID: 20000051. The perimeter enforces stringent checks on:

  1. User-Agent Integrity: Requires verified modern browser signatures (e.g., Google Chrome or Microsoft Edge desktop strings).
  2. TLS Fingerprinting: Inspects JA3/TLS handshake ciphers to filter out unauthorized automated scrapers.
  3. Rate-Limiting: Restricts burst requests across catalog search endpoints to protect backend PHP-FPM workers.
