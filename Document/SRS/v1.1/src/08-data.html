6. Data Requirements

This section describes the information MCMS must hold, as a conceptual model. It names the main entities and their relationships so that reviewers can check that every record required by the Guide exists, and so that the SDD can derive the physical database design. Table names, column types and indexes belong to the SDD.

6.1 Conceptual Data Model

The model is shown in three parts. The most important property is visible in all three: each recognition stage is its own entity (approval decision, Digital Badge, credential, QV record, ACR, ABC deposit, transfer decision, redemption event), never a status field on another entity (D-15).
