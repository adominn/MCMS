8. Shared Authenticated & Shell Pages Analysis

The Shared Authenticated & Shell pages provide consistent system-wide infrastructure across all logged-in personas. These services unify global search, personal data privacy, multi-channel notifications, cross-module task coordination, institutional reporting, and document archival.

8.1 Universal Task Queue (IR-07)

A. Page Information

  • Page Names: Universal Tasks Queue (/tasks), Task Detail & Direct Action (/tasks/{id})
  • Role: All Authenticated Staff (Lecturer, Deputy Dean, CODL Admin, Reviewer)
  • Exact Routes: GET /tasks, GET /tasks/{id}
  • Page Type: Work Queue / Action Routing Hub
  • Related Database Tables: tasks, users, role_assignments, ptjs
  • Related Components & Controllers: App\Modules\Identity\TaskController, Views: tasks, tasks-show

B. Intended Functionality

Serves as the post-sign-in landing page for all staff personas (IR-07). Aggregates all open, actionable items assigned to the user individually or to their active role within their faculty PTj scope. Features area tabs (Proposals, Offerings, Results, Credentials, Deposits, Transfers), keyword search, overdue flagging based on alerts.decision_overdue_days, and direct action routing.

C. Current Implementation

Fully functional and verified in Playwright flow FL-01. Accessing /tasks/{id} automatically redirects the user directly to the target record where the work is performed (e.g., clicking a proposal task opens /approvals/{id}).

D. Functionality Status

Status: Fully Working. Dynamic role scoping and automated task completion operate reliably.

8.3 Profile, Personal Data Governance & Session Control

A. Page Information

  • Page Names: User Profile (/profile), Update Preferences (POST /profile/preferences), Data Correction Request (POST /profile/data-correction), Terminate Session (POST /profile/sessions/terminate)
  • Role: All Authenticated Users
  • Exact Routes: GET /profile, POST /profile/preferences, POST /profile/data-correction, POST /profile/sessions/terminate
  • Page Type: User Profile, PDPA Compliance & Security Dashboard
  • Related Database Tables: users, sessions, notification_preferences, corrections, audit_events
  • Related Components & Controllers: App\Modules\Identity\SearchController, View: profile

B. Intended Functionality

Compliance and account management: (1) Personal Information: Displays official name, staff/student ID, verified email, and assigned roles. (2) Notification Preferences: Toggles granular email and in-system notification delivery per event category. (3) Session Governance: Displays all active web sessions with IP addresses, browser agents, and last activity timestamps. Allows terminating foreign sessions. (4) PDPA Data Rights: Allows users to submit formal personal data correction requests (e.g., legal name spelling change) which are logged into the audit chain for administrative verification.

C. Current Implementation

Fully implemented and verified in Playwright flow FL-01. Session termination invalidates target sessions in the sessions table. Correction requests log to corrections.

D. Functionality Status

Status: Fully Working. Privacy controls and session security are operational.

8.6 Ten Standard System Reports (MD-15)

A. Page Information

  • Page Names: Reports Hub (/records/reports), Report View (/records/reports/{kind}), CSV Export (/records/reports/{kind}/csv), Print View (/records/reports/{kind}/print)
  • Role: Lecturer, Deputy Dean, CODL Administrator
  • Exact Routes: GET /records/reports, GET /records/reports/{kind}, GET /records/reports/{kind}/csv, GET /records/reports/{kind}/print
  • Page Type: Institutional Business Intelligence & Regulatory Reporting
  • Related Database Tables: report_runs, offerings, enrolments, credentials, qv_records, acrs, transfer_applications, credit_ledger_entries, cqi_actions, stackable_plans, suspensions
  • Related Components & Controllers: App\Modules\Records\RecordsController, Views: records.reports, records.report

B. Intended Functionality

Generates the 10 official regulatory reports required by MQA and Senate (FR-reports):

  1. offerings: Cohort delivery performance and enrolment rates.
  2. enrolments: Learner retention, withdrawal, and completion statistics.
  3. credentials: Issued certificates, badges, corrections, and revocations.
  4. quality: Stand-alone SAMC Quality Verification status and expiry tracking.
  5. deposits: Academic Credit Records and national ABC bank deposit totals.
  6. transfers: Credit transfer applications, approval rates, and granted credits.
  7. redemption: Credit ledger redemption lifecycle and validity states.
  8. actions: Open CQI improvement actions and effectiveness evaluations.
  9. plans: Individual stackable pathway plans and institutional credit shares.
  10. suspensions: Active suspensions, terminations, and periodic review outcomes.
All reports are strictly scoped to the user's faculty (deputy dean) or system-wide (admin). Every report execution is logged in report_runs with user ID, execution parameters, and record counts. Results can be viewed on screen, exported as CSV, or printed via A4 layout.

C. Current Implementation

Fully functional and verified in Playwright flow FL-24. Queries respect faculty PTj boundaries. CSV exports and printable layouts execute deterministically.

D. Functionality Status

Status: Fully Working. Scoped reporting, CSV export, print layout, and run logging operate as specified.
