7. CODL Administrator Pages & Functionality Analysis

The Centre for Open and Distance Learning (CODL) Administrator role (Persona S1, P5) represents the technical system operator. In accordance with Decision D-28, CODL has no academic decision authority; the role is strictly focused on user identity governance, reference data management, system configuration, external integration hubs, audit integrity verification, and data retention.

7.1 User Administration & Role Provisioning (MD-01)

A. Page Information

  • Page Names: User Directory (/admin/users), User Profile & Roles (/admin/users/{user}), Assign Role (POST /admin/users/{user}/roles), Revoke Role (POST /admin/users/{user}/roles/{assignment}/revoke), Toggle Status (POST /admin/users/{user}/status/{to})
  • Role: CODL Administrator (codl_admin)
  • Exact Routes: GET /admin/users, GET /admin/users/{user}, POST /admin/users/{user}/roles, POST /admin/users/{user}/roles/{assignment}/revoke, POST /admin/users/{user}/status/{to}
  • Page Type: User Directory & RBAC Security Administration
  • Related Database Tables: users, role_assignments, ptjs, audit_events
  • Related Components & Controllers: App\Modules\Identity\UserAdminController, Views: admin.users.index, admin.users.show

B. Intended Functionality

Governs user identities across all departments (FR-05, FR-06, FR-13, FR-23). Features: (1) Keyword search by staff/student ID, name, email, or role, (2) User deactivation/reactivation (deactivated users are blocked from sign-in and audited), (3) Scoped role assignments with effective start and end dates (e.g., assigning Deputy Dean scoped strictly to FTMK), and (4) Role revocation with mandatory audit justification.

C. Current Implementation

Fully functional and verified in Playwright flow FL-17. Role assignments validate that privileged staff roles (Deputy Dean, CODL Admin) require MFA. Scoping correctly binds to PTj faculty records.

D. Functionality Status

Status: Fully Working. Role lifecycle and permission checks operate reliably.

Modifications create immutable numbered versions. - Reference Data: Maintains institutional entities (Faculties, Degree Programmes, Parent Courses) via manual web forms or bulk CSV imports.

C. Current Implementation

Fully implemented and verified in Playwright flow FL-17. Setting modifications validate type constraints and log full before/after snapshots into the audit chain.

D. Functionality Status

7.3 UCreds Integration Hub & File Exchange (MD-06)

A. Page Information

  • Page Names: UCreds Hub (/admin/ucreds), Enrolment Export (/admin/ucreds/export/{offering}), Enrolment Manifest (/admin/ucreds/export/{offering}/manifest), Check Results CSV (POST /admin/ucreds/check), Import Audit Report (/admin/ucreds/imports/{id}), Download Errors (/admin/ucreds/imports/{id}/errors.csv), Stage Valid Results (POST /admin/ucreds/imports/{id}/stage), UCreds Courses (/admin/ucreds/courses)
  • Role: CODL Administrator (codl_admin)
  • Exact Routes: GET /admin/ucreds, GET /admin/ucreds/export/{offering}, GET /admin/ucreds/export/{offering}/manifest, POST /admin/ucreds/check, GET /admin/ucreds/imports/{id}, GET /admin/ucreds/imports/{id}/errors.csv, POST /admin/ucreds/imports/{id}/stage, GET /admin/ucreds/courses
  • Page Type: Integration Hub, File Parser & Staging Pipeline
  • Related Database Tables: export_files, import_files, import_row_errors, enrolments, assessment_results, ucreds_courses
  • Related Components & Controllers: App\Modules\Learning\UcredsController, Views: ucreds.index, ucreds.manifest, ucreds.report, ucreds.courses

B. Intended Functionality

Executes deterministic CSV data interchange with UCreds (Moodle LMS): (1) Enrolment Export: Compiles registered learner rosters in standardized template enrol v3, generating identical byte output and SHA-256 hashes for identical data. (2) Check File: Validates imported grades against schema rules without altering live database records. Detects duplicate files via SHA-256 hash checking (SDD 6.2.3). (3) Rejected Rows Report: Generates downloadable CSV containing specific row numbers and validation error reasons (e.g., unregistered student ID, mark exceeds 100). (4) Staging: Commits valid rows to assessment_results in pending verification state. (5) UCreds Courses: Reference catalog of 59 verified pilot courses (D-34).

C. Current Implementation

Fully functional and verified in Playwright flow FL-07 and scenario Act 2. Staging handles partial validation: valid rows stage successfully while rejected rows are isolated in import_row_errors.

D. Functionality Status

Status: Partially Working (By Design). Core file checking, error reporting, and staging operate reliably. File scanning and storage run within local disk storage (storage/app/private/ucreds) pending an enterprise object store and virus scanner.

7.4 Adapters, Cryptographic Audit Trail & Retention Governance (MD-15, MD-16)

A. Page Information

  • Page Names: Integration Adapters (/admin/adapters), Retry Call (POST /admin/adapters/calls/{id}/retry), Notification Log (/admin/notification-log), Demo Clock (/admin/demo-clock), Audit Trail (/admin/audit), Verify Hash Chain (POST /admin/audit/verify), Retention Governance (/records/retention), Apply Hold (POST /records/retention/holds), Lift Hold (POST /records/retention/holds/{id}/lift), Dispose (POST /records/retention/{category}/dispose)
  • Role: CODL Administrator (codl_admin)
  • Exact Routes: GET /admin/adapters, POST /admin/adapters/calls/{id}/retry, GET /admin/notification-log, GET /admin/demo-clock, POST /admin/demo-clock, POST /admin/demo-clock/jobs, GET /admin/audit, POST /admin/audit/verify, GET /records/retention, POST /records/retention/holds, POST /records/retention/holds/{id}/lift, POST /records/retention/{category}/dispose
  • Page Type: Integration Hub, Security Audit & Legal Compliance Dashboard
  • Related Database Tables: integration_calls, notifications, audit_events, audit_chain_heads, retention_holds, disposal_records
  • Related Components & Controllers: AdapterController, NotificationController, DemoClockController, AuditController, RetentionController, Views: admin.adapters, admin.notification-log, admin.demo-clock, audit.index, records.retention

B. Intended Functionality

Technical and legal governance: - Adapters & Notifications: Monitors external API calls (payment gateway, SMS, email), displays latency and error payloads, and enables manual retries. - Demo Clock (FL-19): Test-only simulation clock that advances system time to test time-based events (credit expiry, QV lapse) without tampering with database records. Strictly blocked in production environments. - Cryptographic Audit Trail (FR-254): Implements an append-only log where every state change is linked to the prior record via a SHA-256 hash chain. "Verify Chain" traverses the chain to detect unauthorized database tampering. - Retention & Disposal (FR-retention): Applies legal retention periods to non-academic logs. Supports legal holds that freeze disposal. Disposal permanently purges eligible records and issues a signed certificate of disposal.

C. Current Implementation

Fully functional and verified in Playwright flows FL-17, FL-18, and FL-24. Hash chain verification successfully detects modified payloads. Legal holds immediately block disposal actions.

D. Functionality Status

Status: Fully Working. Audit integrity, retry mechanisms, and retention rules operate as specified.
