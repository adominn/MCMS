Executive Summary

This audit delivers an exhaustive functional and technical evaluation of the UTeM Micro-Credential Management System (MCMS / ACESS). Built to support UTeM's lifelong learning and Malaysian Qualifications Framework (MQF) credit-bearing initiatives, MCMS implements the approved clickable prototype (D-38) across a modular Laravel 13 architecture connected to a PostgreSQL database schema.

Audit Objectives & Scope

The audit was executed under rigorous directives to identify all registered pages, evaluate actual versus intended behavior, trace database operations, verify role-based permissions, map end-to-end user flows, and identify disconnected or unfinished workflows. The scope encompasses:

  • All Seven (7) User Roles / Actors: Public / Guest, Student, Lecturer, Reviewer & Industry Expert, Deputy Dean, CODL Administrator, and Shared Authenticated Shell.
  • Complete Route Inventory: 221 registered routes (116 GET/HEAD endpoints and 105 POST/PUT state-transition actions).
  • Presentation Layer: 126 Blade templates across 24 module view directories.
  • Data Layer: 91 relational database tables across 20 schema migrations.
  • Execution & Integration: 36 module controllers, background event listeners, and external adapters.

Key Audit Findings

The system exhibits strong architectural discipline, with an append-only cryptographic audit chain (MD-15), strict separation of academic and administrative duties (D-28), and a fully functioning four-act demonstration scenario (FL-19) verifying core curriculum, learning, credit banking, and quality verification lifecycles. However, several critical gaps must be addressed before production pilot readiness:

  1. File Storage & Scanning Stand-Ins: Multiple production workflows (Quality Verification evidence, offering readiness evidence, UCreds CSV uploads) store textual file references rather than binary files in an object store with automated virus scanning.
  2. Server-Side PDF Generation: Official legal credentials (A4 certificate, student receipt, Academic Credit Record, Senate decision pack, transfer letter) rely on client-side browser print rendering rather than deterministic server-side PDF compilation.
  3. Bilingual UI Localization: While header toggles and Malay headings exist (lang/ms.json), subheadings, table headers, buttons, and validation messages remain predominantly in English.
  4. Asynchronous Processing Dependencies: File imports and 500-credential issuing batches run synchronously within HTTP requests, awaiting Redis/Horizon queue worker infrastructure.
