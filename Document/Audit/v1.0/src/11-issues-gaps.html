10. System Deficiencies, Gaps & Redundancies Analysis

This section consolidates all architectural defects, UI/backend discrepancies, redundant screens, missing templates, and security considerations identified during the comprehensive audit.

10.1 Frontend vs Backend Discrepancies

Module / Feature Frontend UI Presentation Actual Backend Implementation Impact & Risk Remediation Requirement
Quality Verification Evidence (MD-10) UI presents file attachment inputs with descriptions for 6 MQA evidence categories. Stores textual file references / URLs in qv_evidence.file_reference; no binary upload or virus scan. Medium. File integrity cannot be cryptographically proven without binary hashing. Implement S3/MinIO enterprise object storage service with ClamAV virus scanning.
Cohort Readiness Evidence (MD-04) Lecturer checklist presents "Attach Evidence" file fields. Backend accepts text notes; does not store binary files in object store. Low. Operational workaround in place for pilot. Connect file upload handler to stored files service upon activation.
UCreds CSV File Import (MD-06) UI allows uploading grades and badge CSV files. Files are stored on local web server filesystem (storage/app/private/ucreds); parsing runs synchronously inside HTTP request. High. Large CSV imports (500+ rows) risk HTTP timeout (504) or server memory exhaustion. Move CSV parsing and row validation to asynchronous queue workers (Redis/Horizon).
Drawer Side Panels (UIUX Spec 4.2) Prototype specifies sliding right-hand drawers for quick record inspection. Drawers are absent in Blade views; interactions navigate to full pages or use inline accordion folds (details.fold). Low (UX Consistency). D-38 permits inline summary-first presentations. Retain current inline fold/tab pattern; drawers are unnecessary overhead for server-rendered Blade.

10.2 Redundant & Overlapping Pages Analysis

Several pages exhibit functional overlap and require architectural decisions regarding whether to retain, merge, or redesign them:

1. Internal Achievement Record (/my-record) vs Admin Record (/records/{enrolment})

  • Current Situation: /my-record renders the student's personal internal achievement record, while /records/{enrolment} renders an identical view for administrative review. Both use the records.show / records.mine Blade template.
  • Assessment: RETAIN BOTH, MAINTAIN DISTINCT ROUTES. Although the presentation template is identical, the authorization scopes are fundamentally different: /my-record is strictly user-scoped to the signed-in student, whereas /records/{enrolment} enforces faculty PTj authorization for Deputy Deans and CODL staff. Merging them would introduce complex conditional authorization logic into a single endpoint.

2. Credit Ledger (/my-credit) vs ACR Detail View (/my-credit/{id})

  • Current Situation: /my-credit displays the balance of banked credits in ABC, while /my-credit/{id} displays the detailed Academic Credit Record and legal consent submission form.
  • Assessment: RETAIN AND ENHANCE. In accordance with D-38's Summary-First rule, the ledger provides the high-level credit balance overview, while the detailed legal text, MQA accreditation metadata, and consent buttons are properly isolated on the detail screen.

3. Printable Proposal View (/proposals/{id}/print) vs Senate Pack (/approvals/{id}/pack)

  • Current Situation: Both pages display an aggregated, non-tabbed representation of a micro-credential proposal.
  • Assessment: MERGE INTO STANDARDIZED TEMPLATE. The Printable Proposal view was developed for the authoring lecturer, while the Senate Pack was designed for the Deputy Dean. Both should share a single unified printable Blade component (layouts.print) with a conditional banner for Senate meeting metadata.

10.3 Missing Pages & Technical Gaps

The audit identified the following missing templates and incomplete backend services:

  1. Official Senate Credit Transfer Decision Letter (DOC-12):
    Issue: When a Deputy Dean approves or rejects a credit transfer application, the decision is stored in transfer_decisions and viewable in the web table. However, the formal official Decision Letter (DOC-12) required for the student's academic file and Pejabat Pendaftar admission submission has no printable A4 template.
    Remediation: Implement transfer.letter Blade view in layouts.print.
  2. Suspension Notice Document Template (DOC-13):
    Issue: When an offering is suspended, the system dispatches an in-system notification. A formal printable suspension notice template exists in monitoring/suspension-notice.blade.php, but it is not linked from the student's Document Center (/documents).
    Remediation: Add suspension notices to the document center repository query.
  3. Server-Side PDF Binary Compilation:
    Issue: Certificates, receipts, ACRs, and reports currently rely on the browser's native print-to-PDF functionality. In automated batch workflows (e.g., emailing a certificate upon graduation or exporting 500 credentials), client-side printing cannot execute.
    Remediation: Integrate a headless PDF renderer (Playwright Core / Chromium) into the Laravel backend to generate true PDF binaries for downloadable storage.
  4. Full Bahasa Melayu Translation Coverage:
    Issue: While the top navigation and static page <h1> headers are translated via lang/ms.json, table column headers, form input labels, validation alert messages, and button text remain in English.
    Remediation: Wrap all UI strings in Blade views with the translation helper __() and expand lang/ms.json to achieve 100% bilingual compliance.
