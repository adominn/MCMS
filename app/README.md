# MCMS application (Release 1, Laravel 13)

Built from SDD v1.1 and the PRD increments. Status: increment 1.1 Foundation done (except Entra ID sign-in, OI-03, and Redis/Horizon); increment 1.2 Curriculum started.

## Run

```
docker compose up -d          # MySQL 8.4 LTS on port 3306 (PostgreSQL on 5433 preserved as backup)
composer install
cp .env.example .env && php artisan key:generate
php artisan migrate --seed
php artisan serve             # sign in at /signin with the test sign-in (port 8110)
php vendor/bin/pest           # 366 feature tests passed (100% green, 5,225 assertions)
npm install && npm run test:e2e   # Playwright flows (database mcms_e2e on MySQL)
```

**Signing test (the SDD risk).** `ml/json-ld` 1.2, the only maintained PHP JSON-LD library, implements JSON-LD 1.0: it fails on the VC v2 context (JSON-LD 1.1: `@protected`, scoped contexts) and has no RDFC-1.0 canonicalisation, so the Data Integrity proof `eddsa-rdfc-2022` cannot be produced in PHP without writing a canonicaliser. The fallback of the SDD is used: the same Ed25519 key signs the credential as a VC-JWT (`alg` EdDSA, `kid`, public keys published as a JWKS). Open Badges 3.0 allows this proof format. The library was removed again. Revisit if a PHP RDFC-1.0 implementation appears.
