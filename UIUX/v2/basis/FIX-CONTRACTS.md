# Shared contracts for the fix round (26 Oct 2026)

Several fixes cross files. Each fixer edits only their own file; these contracts say who writes what, so the pieces meet.

| Topic | Owner (writes) | Reader | Contract |
|---|---|---|---|
| Proposal comments | dd-a seeds `s.ddComments` (array, `mc` field), adds DBC4 = answered blocking comment with a response | lecturer, dd-a | One store only. Status words lowercase `open`, `answered`, `resolved`. Lecturer "Respond" sets `answered` + `response`. Deputy dean resolves only `answered`. lecturer.js deletes `lecComments` and uses `s.ddComments` (with the ensure pattern). X2 comments push into `s.ddComments` with `role:'Industry expert'`, `blocking:false`. |
| Cohort results | lecturer `subres` writes `co.learners = [{n, id, m:[..], fin, res, src, flag}]` | dd-a | dd-a also reads `resOf(s,c) = c.learners || s.lecRes[c.id].learners`, computing fin/res from `MC.mc(c.mc).weights` if missing. `res` is 'Pass', 'Fail' or 'Held'. |
| Readiness checklist | lecturer owns `s.lecRead[cohortId] = { items:[{k, t, st:'Yes'|'Not yet'|'Not applicable', ev, owner:'Lecturer'|'CODL'|'Deputy dean'}], sent:boolean }` and seeds DS-2027-1 (12 items, lecturer item "Facilitator qualification evidence" Not yet) | dd-a | Both use the same 12 item titles (lecturer.js is the source; dd-a reads them). `cohort.readiness` = count of items with st 'Yes' or 'Not applicable', kept in sync by whoever changes an item. dd "Accept evidence" sets that item `st:'Yes'`, `ev` += ' (accepted by the deputy dean)'. "Not ready" sets `sent=false`. |
| Material change | lecturer writes `m.pending = { version, status:'Submitted', kind:'material', summary, created }` | dd-a | dd-a shows it at `dd/proposal/:id?v=pending`: assign reviewers → `In review` → endorse → `Pending approval` → Senate. On Approved: `m.version = pending.version`, push the old version into `m.versions` as Superseded, delete `m.pending`. Minor change: lecturer pushes a dd task "Acknowledge minor change"; dd-a gives it a simple acknowledge act on dd/proposal/:id. |
| Enrolment completion | dd-a `finalize` sets enrolments in the cohort to `Completed` (issued) or `Not completed` | student | student derives the waiting label from the cohort: results not Verified → "Waiting for result verification"; Verified and completion not confirmed → "Waiting for completion to be confirmed". |
| Transfer outcomes | student new application line `match` from lookup `{'DS|BITS 1123':['Full','Full','Full','Full'], 'CND|BITU 3973':['Full','Partial','Full','None']}`, default `['Not rated',…]` | dd-b | dd-b blocks Approve when any match is 'None', empty or 'Not rated'. Decision fields: `t.status`, `t.reason`, `t.decidedOn`, `lines[].decision`. "More evidence needed" → student upload reopens the dd task (`done=false`). |
| QV periods | dd-b pushes old `m.qv` into `m.qvHistory` before writing a new result | dd-a, student, public | A SAMC credit/QV claim holds for a cohort if any period in `[m.qv, ...(m.qvHistory||[])]` with status Quality-Verified covers the cohort dates. |
| Suspension | dd-b sets `m.status='Suspended'|'Terminated'` and not-started Open/Full cohorts to `Cancelled` | student, public | Catalogue and register show only Approved micro-credentials' Open/Full cohorts; Suspended → "Registration is closed: this micro-credential is suspended." |
| Category names | lead adds `MC.CATNAME = { UMC:'Unbundled Micro-Credential', SAMC:'Stand-alone Micro-Credential', MCE:'Micro-Credential Eksekutif' }` to core.js | all | Use it instead of local long names. |
| Documents (PDF) | docs builder: routes below | all | Replace every fake download/print/export toast with `data-go` to the document. Routes: `doc/receipt/:enrolmentId`, `doc/enrolment/:enrolmentId`, `doc/certificate/:credentialId`, `doc/credential/:credentialId` (JSON), `doc/record/:who` (amir), `doc/acr/:acrId`, `doc/proposal/:mcId`, `doc/pack/:mcId`, `doc/report/:reportId`, `doc/abc/:batchId`, `doc/qvpack/:mcId`, `doc/transfer/:transferId`, `doc/suspend/:mcId`, `doc/import/:fileName`, `doc/audit`, index `doc/index`. Reports' Open/PDF go to `doc/report/:id`; CSV/Excel may stay toasts or go to the same document. |
| Privacy | all | — | A role screen must never link into another role's screen in a way that switches persona for an action that role may not take (e.g. CODL → lec/cohort, dd → codl/audit). Plain text instead. |
| Copy | all | — | No requirement IDs (fr-…, BR-…, D-…) in visible text; use `MC.trace(...)` lines if traceability is wanted. |
